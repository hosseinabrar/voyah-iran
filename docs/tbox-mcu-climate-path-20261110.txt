- 0x10042744 passes request+0x12 to 0x1004234c (8-byte copy).
- 0x10042750..0x10042798 builds receipt with two zero status bytes and sends
  it via 0x1003749a. It does not wait for random/auth or actual vehicle state.
- 0x1004234c queue helper: six-entry table 0x1007e8dc; matching enabled entry
  sets pending byte in 9-byte slot at 0x08009000. 0x58 is enabled.
- 0x1007f0d4 cyclic wrapper calls 0x1004242c then 0x100424a2.
- 0x1004242c consumes pending byte and writes 2 to scheduler slot array
  0x080289cc; this is software scheduling, NOT hardware TX confirmation.
- 0x10029d6c and 0x1002a514 consume that scheduler state. Scheduler path
  reaches 0x1002a02c, calls table callback +0x24 and then lower transport
  function 0x10033142 if callback returns1.
- 0x10076726 is the 0x58 payload provider: calls 0x100423c2 to copy queued
  eight bytes to the caller's buffer, then returns1. It has no local power
  or READY check. This alone does not establish all upstream/downstream
  conditions or that the CAN controller physically transmits.
