Findings
1. X authenticated remote handler 0x100426e6 reads request and assigns auth
   class 1 for 0x58, class 2 for 0xA8. Only those two IDs call the queue helper
   0x1004234c. Other IDs still reach the receipt acknowledgement (zero status).
   Thus a successful receipt is not evidence of queued CAN transmission.
2. C corresponding handler 0x10042536 adds class 3 for 0x68 and a dedicated
   payload queue (branch 0x1004265c onward). This is a concrete capability
   difference relevant to driver/passenger seat ventilation. It does not
   establish intentional regional locking.
3. X queue helper 0x1004234c copies 8 bytes then marks a slot pending only if
   table entry byte+4 is 1. Static six-entry table at 0x1007e8dc:
   ID 0x48 slot0 flag1; 0x58 slot1 flag1; 0xA8 slot4 flag1;
   0x7E slot3 flag0; 0x4FE slot6 flag0; 0x3F7 slot5 flag0.
   Queue pump 0x1004242c transfers pending flags to transmit slots.
   In particular 0x58 is NOT globally disabled in this table. Flag0 entries
   require further call-path analysis, not a conclusion that all such IDs
   are blocked throughout the firmware. 0x68 has no entry in this table.
4. Both have random-challenge wait/failure paths. X No-random at 0x10042550;
   C at 0x10069d80. X retries after timer 0x7d0 and terminates after counter2;
   C uses counter0xc8 and counter2 (tick duration not established).
   C also does not unconditionally execute authenticated requests.
5. Packet layouts differ: X queues payload starting request+0x12; C copies
   from request+0x11. Compare the complete matching MPU/MCU transport before
   interpreting this as a defect; never compensate with guessed raw bytes.

Live evidence
Client test with vehicle OFF reached live MCU receipt (0,0), but power remained
OFF, AC-on was withheld, and MCU logged Auth Recv No random at 16:46:46.092 and
16:49:21.807. This establishes failure waiting for the challenge, not whether
its request was absent on the wire or the response was lost/refused.

Conclusion
There is a real narrower authenticated command path in the inspected X image,
especially for seat ventilation. No unconditional X-only block was found for
0x58 hazard/power requests in this inspected path. Intentional restriction
analogous to the modem patch is unproven. Identify active MCU firmware and
observe challenge request/response on CAN before selecting any correction.
No MCU flash, patch, key extraction, or authentication bypass was performed.
