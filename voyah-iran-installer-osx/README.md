# نصاب وویا ایران برای macOS

پروژهٔ بومی SwiftUI با هدف سازگاری macOS 12 به بالا، با موتور .NET 8 مشترک با نصاب ویندوز. خروجی Universal برای Intel و Apple Silicon ساخته و بررسی شده است؛ تست اجرا روی Intel و macOS 12 هنوز انجام نشده است.
پروژهٔ مک کنار `voyah-iran-installer` قرار دارد. هر checkout از **هسته، APK و پچ‌های همان برنچ** استفاده می‌کند؛ ساخت نسخهٔ ۲٫۰٫۳ کد لانچر را وارد آن برنچ نمی‌کند.

## Publish یکپارچه

`Publish.command` را اجرا کنید. روند انتشار:

1. خواندن نسخه از Gradle و نام انتشار از پروژهٔ نصاب همان برنچ.
2. اجرای `:app:assembleRelease` با کلید اصلی اندروید و تنظیم انتخاب‌شدهٔ R8.
3. بررسی امضای APK، پکیج، versionCode/versionName و قراردادهای واسط.
4. در صورت فعال‌بودن پروتکشن، اجرای همان `protect_raha.py` ویندوز، بررسی گزارش `application-v2`، zipalign و امضای مجدد با همان گواهی.
5. بسته‌بندی فایل‌های یکسان در یک باندل مشترک و فایل‌های متفاوت در دو باندل معماری. APK فقط یک‌بار ساخته و ذخیره می‌شود. تمام فایل‌ها SHA-256 دارند؛ ترکیب باندل مشترک با هر معماری توسط موتور میزبان استخراج و بررسی می‌شود. فشرده‌سازی ZIP سطح ۹ است و سورس جاوا همراه نصاب قرار نمی‌گیرد.
6. ساخت موتور مستقل .NET برای هر دو معماری، کامپایل رابط SwiftUI برای `arm64` و `x86_64`، ادغام رابط با `lipo`، امضای محلی یک `.app` و ساخت یک ZIP.

بیلد ناموفق اندروید، انتشار را متوقف می‌کند؛ APK قبلی جایگزین نمی‌شود. این نسخهٔ pipeline عمداً cache ده‌دقیقه‌ای نصاب ویندوز ندارد؛ Gradle خودش خروجی‌های معتبر بدون تغییر را بازاستفاده می‌کند. فایل `build-report.json` نسخه، معماری، هش APK و ZIP، گواهی و انتخاب R8/پروتکشن را ثبت می‌کند.

خروجی‌ها مانند ویندوز مستقیم داخل `dist` و با نام ثابت هستند:

- برنچ لانچر: `voyah-iran-installer_launcher.app` و `voyah-iran-installer_launcher.zip`
- نسخهٔ ۲٫۰٫۳: `voyah-iran-installer_2.0.3.app` و `voyah-iran-installer_2.0.3.zip`

هر Publish موفق، خروجی قبلی همان نام را جایگزین می‌کند؛ پوشه یا شناسهٔ تصادفی به خروجی نهایی اضافه نمی‌شود. فایل گزارش هم با نام `<name>.build-report.json` کنار آن‌ها قرار می‌گیرد. ابتدا همهٔ مراحل در `.build` کامل می‌شوند؛ خطای بیلد یا بسته‌بندی خروجی قبلی را دست‌نخورده می‌گذارد و خطای عادی هنگام جایگزینی باعث بازگرداندن نسخهٔ قبلی می‌شود. اجرای هم‌زمان دو Publish در یک checkout ممنوع است. خروجی توسعه پسوند `-development` دارد و جای نسخهٔ کامل را نمی‌گیرد. پوشه‌های خروجی قدیمی خودکار حذف نمی‌شوند.
خروجی نهایی برای هر دو معماری یکسان است. رابط براساس معماری پردازش، `backend/osx-arm64` یا `backend/osx-x64` و باندل متناظر در `payloads` را همراه `payloads/common.zip` انتخاب می‌کند. مانیفست هر معماری هش تمام فایل‌های مشترک و اختصاصی را دارد؛ فایل تکراری بین دو باندل، فایل اضافی، مسیر ناامن و هش نامعتبر رد می‌شوند. موتور بررسی معماری باندل را هم مستقل انجام می‌دهد. برای اجرا روی Apple Silicon نیازی به Rosetta نیست؛ روی Intel اجزای x64 استفاده می‌شوند.

حداقل هدف کامپایل و Info.plist برابر `12.0` است. APIهای `Layout` و `defaultSize` مخصوص macOS 13 با روش سازگار جایگزین شده‌اند. Publish معماری و حداقل نسخهٔ Mach-O همهٔ اجزای بومی .NET و Java و ADB را کنترل می‌کند؛ اگر وابستگی به سیستم جدیدتری نیاز داشته باشد، انتشار متوقف می‌شود، نه اینکه فقط عدد Info.plist پایین آورده شود. این کنترل استاتیک جای تست روی Intel و macOS 12 را نمی‌گیرد. macOS 12 از چرخهٔ پشتیبانی رسمی فعلی Apple/.NET خارج شده است؛ هدف سازگاری با دستگاه قدیمی، ادعای پشتیبانی امنیتی سازنده نیست.

## پیش‌نیازهای توسعه

- Xcode/Command Line Tools دارای Swift 5.9 یا جدیدتر و SDK مک
- .NET SDK 8
- JDK 25 کامل هم‌معماری با میزبان برای Gradle و دو JDK مک برای بسته‌بندی (`aarch64` و `x64`)
- Android SDK Platform 36، Build Tools 37.0.0 و Platform Tools مک
- Python 3.9+؛ برای پروتکشن Python 3.10+
- کلید اصلی موجود در `../voyah-iran/Keystore/voyahiran` و رمز آن

مسیرها را با `JAVA_HOME`، `ANDROID_HOME` و `VI_DOTNET` یا فایل محلی و ignored زیر مشخص کنید:

```json
{
  "JavaHome": "/absolute/path/to/jdk/Contents/Home",
  "JavaHomeArm64": "/absolute/path/to/arm64-jdk/Contents/Home",
  "JavaHomeX64": "/absolute/path/to/x64-jdk/Contents/Home",
  "AndroidSdk": "/absolute/path/to/android-sdk",
  "Dotnet": "/absolute/path/to/dotnet",
  "Python": "/absolute/path/to/python3"
}
```

محل فایل: `build/Toolchain.local.json`. مسیرهای این فایل نباید وارد Git شوند. cacheهای Publish به‌صورت پیش‌فرض داخل `.build/` پروژه نگهداری می‌شوند؛ گزینهٔ اختیاری `GradleUserHome` امکان اشتراک cache بین دو برنچ در `voyah/work/` را می‌دهد. `VI_PYTHON` هم می‌تواند مسیر Python را تعیین کند. ابزارهای جدید را می‌توان در پوشهٔ اصلی `voyah/work/` نگه داشت؛ تغییر تنظیمات سراسری سیستم لازم نیست.

گزینه‌های خط فرمان `--java-home-arm64` و `--java-home-x64` هم موجودند. برای معماری میزبان، در نبود مسیر اختصاصی از `JavaHome` استفاده می‌شود؛ مسیر معماری دیگر الزامی است. Temurin 25 فعلی `jmods` ندارد، بنابراین پوشه‌های runtime از JDK هر معماری بدون اجرای ابزار معماری دیگر بسته‌بندی می‌شوند. اندازهٔ خروجی نسبت به نسخهٔ تک‌معماری بیشتر خواهد بود. اجرای smoke test جاوا و ADB فقط برای معماری میزبان است و گزارش انتشار آن را صریح ثبت می‌کند.

## تنظیمات امضا و حفاظت

`Build Settings.command` پنجرهٔ رمز و تیک‌های پروتکشن/R8 را باز می‌کند. رمزها در Keychain مک و فقط گزینه‌های غیرمحرمانه در `build/BuildSettings.local.json` ذخیره می‌شوند. DPAPI ویندوز به مک منتقل نمی‌شود. رمز خالی در پنجره، رمز ذخیره‌شده را حفظ می‌کند؛ رمز مستقل کلید اختیاری است.

پیش‌فرض اولین اجرای مک مطابق آخرین انتشار ثبت‌شده در تحویل: **پروتکشن خاموش، R8 روشن**. فعال‌کردن پروتکشن R8 را هم فعال می‌کند. گزینه‌ها را قبل از انتشار عمومی بررسی کنید. هیچ کلید جدیدی ساخته نمی‌شود.

CI می‌تواند رمزها را از `VI_DPT_STORE_PASSWORD` و `VI_DPT_KEY_PASSWORD` تأمین کند. متغیرهای امضا فقط به فرایندهای لازم داده می‌شوند؛ پروتکشن رمز دریافت نمی‌کند. برای alias دیگر از `--alias` و متغیرهای محیطی استفاده کنید؛ پنجرهٔ تنظیمات alias موجود `voyahiran` را مدیریت می‌کند.

```sh
./Publish.command
./Publish.command --no-protection --no-minify
./Publish.command --protection --minify
```

نیازی به APK یا EXE ساخته‌شده روی ویندوز نیست.

## توسعهٔ رابط بدون انتشار اندروید

```sh
./Publish.command --development
```

این گزینه فقط `.app` توسعه‌ای را برای بررسی رابط و موتور می‌سازد، باندل نصب ندارد و هیچ فرمانی به خودرو نمی‌فرستد. جایگزین Publish کامل نیست. می‌توان `Package.swift` را هم در Xcode باز کرد؛ اجرای مستقیم Swift Package همین حالت بدون باندل را دارد.

## امکانات

### تطبیق رابط با ویندوز

رنگ‌های ثابت، اندازهٔ اولیهٔ پنجره، هدر و پاورقی، کارت نصب، ترتیب دکمه‌ها و صفحهٔ جداگانهٔ مراحل/گزارش از XAML نصاب ویندوز گرفته شده‌اند. نصب APK، حذف، مجوزها و راهنمای اتصال پنجره‌های مستقل دارند؛ راهنما مثل ویندوز زمینهٔ سفید دارد. ابزار CAN در منوی «ابزارهای تکمیلی» حفظ شده تا صفحهٔ اصلی با ویندوز هم‌چیدمان بماند.

قاب پنجره و کنترل‌های سیستمی متعلق به macOS هستند و فونت سیستم جایگزین Segoe UI ویندوز است؛ تطابق پیکسل‌به‌پیکسل رندر دو سیستم ادعا نمی‌شود. تست `test_ui_contract.py` رنگ‌ها و ترتیب دکمه‌ها را با XAML همان برنچ مقایسه می‌کند.

برای بررسی پنجره‌ها بدون خودرو، در خروجی `--development` متغیر `VI_MAC_UI_PREVIEW=1` منوی پیش‌نمایش با داده‌های ساختگی را فعال می‌کند. این حالت فقط در نبود باندل در دسترس است، موتور نصب را اجرا نمی‌کند و عملیات خودرو غیرفعال می‌ماند.

- نصب کامل وویا ایران، بکاپ و پچ اختصاصی خودرو، نصب واسط و بررسی پس از ریبوت
- نصب APK، نشان، مایکت و Gboard همراه split؛ مدیریت پنج گروه مجوز پس از نصب
- فهرست و حذف برنامه‌های قابل حذف، با کنترل دوبارهٔ پکیج و تأیید کاربر
- بازکردن برنامه، تنظیم ساعت، ریبوت نمایشگر و رمز روز منوی مهندسی
- Logcat زنده، شنود CAN و علامت‌گذاری گزارش با همان موتور ویندوز
- گزارش فارسی، مراحل نصب، حفظ بکاپ و جلوگیری از بستن معمولی پنجره حین عملیات

اسکن اتصال فقط‌خواندنی است. هر عملیات به serial منتخب و تنها اتصال آماده محدود می‌شود. تغییر مبهم خودرو خودکار تکرار نمی‌شود. اپ اصلی با دکمهٔ نصب کامل به‌روزرسانی می‌شود تا واسط هم همراه آن تغییر کند.

داده‌های کاربر نهایی در `~/Library/Application Support/VoyahIran/Installer` شامل `Logs`، `Backups`، `Reports` و `Cache` نگهداری می‌شود. برای تست توسعه، `VI_MAC_DATA_ROOT` را به مسیری داخل `voyah/work` بدهید. پس از نصب موفق و تأیید پس از ریبوت، بکاپ‌های موقت bridge روی خودرو و پوشه‌های قدیمی پچ و کش نصاب پاک می‌شوند؛ کش فعال تا خروج نصاب باقی می‌ماند. نسخه‌های اصلی فریم‌ور خودرو برای بازیابی سیستم و گزارش‌های کاربر حذف نمی‌شوند. فایل‌های نصب ناموفق تا موفقیت نصب بعدی حفظ می‌شوند. فایل‌های قفل‌شده یا مسیرهای دارای لینک با گزارش هشدار نگه داشته می‌شوند.

## اعتبارسنجی و توزیع

```sh
dotnet run --project tests -c Release
python3 -m unittest discover -s tests -p 'test_*.py' -v
dotnet run --project ../voyah-iran-installer/tests/VoyahIran.Installer.Tests -c Release
```

در اجرای تست‌ها `TMPDIR` را به پوشهٔ کاری دلخواه بدهید. تست‌های مشترک نصب، خطا، بکاپ، USB، reboot و لاگ را بدون خودرو شبیه‌سازی می‌کنند؛ موفقیت آن‌ها تأیید نصب روی خودرو نیست.

امضای پیش‌فرض `.app` از نوع ad-hoc و برای تست محلی است. `--identity` هویت Apple را انتخاب می‌کند، ولی pipeline فعلی notarization خودکار ندارد؛ خروجی را notarized یا آمادهٔ توزیع عمومی معرفی نکنید. حذف quarantine یا خاموش‌کردن Gatekeeper انجام نمی‌شود.
