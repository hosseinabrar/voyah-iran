# نصاب وویا ایران — پچ خودکار کیبورد

پروژهٔ C#، WPF و .NET 8 برای ویندوز ۱۰ و ۱۱، معماری x64. رابط فارسی و راست‌به‌چپ است؛ ظاهر در XAML تعریف شده است. نسخهٔ نصاب 0.2.0 است؛ APK همراه همچنان نسخهٔ تست‌شدهٔ 0.2.2-keyboard است.

## بررسی در Visual Studio

فایل VoyahIran.Installer.sln را در Visual Studio 2022 با workload توسعهٔ دسکتاپ .NET باز کنید. پروژهٔ VoyahIran.Installer را Startup Project قرار دهید.

- ظاهر: src/VoyahIran.Installer/MainWindow.xaml
- رنگ و قالب‌ها: src/VoyahIran.Installer/App.xaml
- وضعیت رابط: MainViewModel.cs
- ترتیب عملیات: src/VoyahIran.Installer.Core/InstallEngine.cs
- اجرای ابزار محلی: JavaFrameworkPatcher.cs
- منطق پچ و بررسی همهٔ کلاس‌ها: tools/patch/FrameworkPatch.java
- نصب و بازیابی فریم‌ور: tools/patch/manage-dynamic-framework.sh

## تغییر مهم

دیگر services.jar آماده در بسته وجود ندارد. نصاب فایل خود خودرو را می‌گیرد و پچ محدود کیبورد را روی همان فایل می‌سازد. تفاوت‌های نسخهٔ فریم‌ور و تغییرات نامرتبط توییکس از فایل دیگری جایگزین نمی‌شوند.

پذیرش فایل به هش ازپیش‌تعیین‌شدهٔ کل JAR وابسته نیست. ساختار متد هدف باید با الگوی بررسی‌شده سازگار باشد. ساختار ناشناخته، هوک ناقص، helper متفاوت یا تغییر پیش‌بینی‌نشده هنگام بازسازی باعث توقف پیش از نصب APK می‌شود. فایل پچ‌شده دوباره پچ نمی‌شود؛ هوک قبلی دقیقاً بررسی می‌شود و نصب فریم‌ور برای آن اجرا نمی‌شود.

## روند یک‌کلیکی

1. تشخیص تنها یک اتصال مجاز، تأیید su 0 و دریافت فایل سیستم با بررسی هش.
2. نگهداری بکاپ فایل فعلی روی لپ‌تاپ، پیش از هر تغییر خودرو.
3. بازکردن JAR با ابزار همراه، یافتن متد کیبورد، اعمال هوک محدود و بازسازی.
4. بررسی دوبارهٔ تمام کلاس‌ها و محتوای ZIP؛ فقط DEX حاوی کلاس هدف از بازسازی گرفته می‌شود. سایر ورودی‌های JAR، از جمله DEXهای دیگر، از فایل خود خودرو حفظ می‌شوند. تغییرات هم‌معنای نمایش Smali، مانند const-string/jumbo و مقدار ضمنی false، نرمال می‌شوند؛ تفاوت اجرایی دیگر پذیرفته نمی‌شود.
5. بررسی مجدد هش فایل خودرو برای تشخیص تغییر هم‌زمان؛ سپس نصب APK و واسط دسترسی.
6. نصب پچ مخصوص همان فایل، با بکاپ نسخهٔ اصلی و فایل‌های پیش‌کامپایل روی خودرو. اسکریپت بلافاصله پیش از جایگزینی هم هش ورودی را کنترل می‌کند.
7. یک ریبوت خودکار فقط پس از موفقیت تمام مراحل.
8. انتظار برای همان serial و boot ID جدید، تأیید پایان بوت، هش‌ها و اجرای واسط؛ سپس بازکردن وویا ایران.

کاربر فقط USB debugging را فعال می‌کند، کابل را وصل می‌کند و نصب را می‌زند. Java، APKTool، Python یا .NET جداگانه لازم نیست. درایور USB سازگار ویندوز همچنان باید خودرو را بشناسد. Gboard همراه بسته نیست و باید روی خودرو نصب باشد؛ انتخاب کیبورد از داخل وویا ایران انجام می‌شود.

## بسته و خروجی

payload/bundle.zip اکنون APK، ADB و DLLها، اسکریپت‌ها، فایل init، APKTool 3.0.3، منبع ابزار پچ، الگوها و Java کم‌حجم Temurin 21.0.12.1+1 را دارد. هش هر فایل در manifest ثبت می‌شود. Java با ماژول‌های لازم، از جمله کامپایلر داخلی برای اجرای فایل سورس ابزار، داخل بسته است. هیچ ابزار یا دادهٔ نصبی هنگام نصب از اینترنت دانلود نمی‌شود.

بستهٔ فعلی به‌روز شده است. برای EXE تک‌فایلی باید Publish با پروفایل WindowsSingleFile انجام شود؛ Build معمولی کافی نیست. در این مرحله EXE جدید تولید نشده است.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build\Publish.ps1
```

خروجی: dist/VoyahIran.Installer.exe. انتشار اول ممکن است runtime مستقل .NET را دریافت کند؛ خود نصاب برای پچ به اینترنت نیاز ندارد.

بعد از تغییر APK، اسکریپت یا ابزار پچ، بسته را قبل از Publish به‌روز کنید:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build\Prepare-Payload.ps1 -PlatformTools "مسیر platform-tools"
```

APK پیش‌فرض از ../voyah-iran/app/release/app-release.apk خوانده می‌شود. Java و APKTool از tools پروژه خوانده می‌شوند؛ برای جایگزین‌کردن آن‌ها پارامترهای -JavaRuntime و -Apktool وجود دارد. نسخهٔ نمایش‌داده‌شدهٔ APK با -AppVersion قابل تعیین است. ساخت Java کم‌حجم برای توسعه‌دهنده با build/Create-JavaRuntime.ps1 و JDK 21 ممکن است؛ کاربر نهایی به این کار نیاز ندارد.

## گزارش و بکاپ

گزارش کامل stdout، stderr، خطاها، مراحل و هش‌ها در رابط و فایل ذخیره می‌شود. رمز واسط از گزارش حذف می‌شود.

- گزارش‌ها: %LOCALAPPDATA%\VoyahIran\Installer\Logs
- بکاپ و جزئیات پچ: %LOCALAPPDATA%\VoyahIran\Installer\Backups
- فایل‌های همراه استخراج‌شده: %LOCALAPPDATA%\VoyahIran\Installer\Cache

هر اجرای پچ یک پوشهٔ مستقل شامل services.jar دریافت‌شده، patch-result.json و فایل‌های بررسی ایجاد می‌کند. این فایل‌ها ممکن است چندصد مگابایت فضا مصرف کنند؛ عمداً برای بررسی فنی باقی می‌مانند.

بکاپ جدید روی خودرو بر اساس هش فایل اصلی جدا می‌شود:

/data/local/tmp/voyahiran-framework-backups/<original-sha256>

اصل JAR، فایل‌های پیش‌کامپایل و restore.sh در آن نگهداری می‌شوند. اسکریپت verity یا SELinux را غیرفعال نمی‌کند. timeout عملیات نوشتن باعث تکرار خودکار یا ریبوت نمی‌شود؛ ممکن است فرمان روی خودرو هنوز در حال اجرا باشد.

## بازگردانی فنی

برای نصبی که واقعاً پچ جدید ساخته، از patch-result.json همان اجرا استفاده کنید:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build\Restore-Framework.ps1 -Record "مسیر patch-result.json" -Adb "مسیر adb.exe"
```

فقط پس از موفقیت بازگردانی، ریبوت کنید. این مسیر به ADB و su 0 نیاز دارد. اگر گزارش AlreadyPatched=true باشد، آن اجرا فریم‌ور را تغییر نداده است؛ باید رکورد نصب اولیه را استفاده کنید. برای پچ قدیمی مبتنی بر فایل آماده، همان Install-KeyboardFramework.ps1 -Action Restore پروژهٔ اندروید همچنان معتبر است و بکاپ قدیمی حذف نمی‌شود.

## وضعیت بررسی

ابزار Java با runtime همراه روی هر دو فایل اصلی موجود پچ ساخت و کد ۷۹۴۲ کلاس در هر فایل را پس از بازسازی بررسی کرد. پچ قدیمی و تکرار پچ جدید بدون تغییر فایل شناسایی شدند. آزمون الگوی ناسازگار پیش از ساخت patched.jar متوقف شد. تست میزبان اسکریپت نصب، نصب مجدد، بازگردانی، تغییر هم‌زمان فایل و خطای عمدی هنگام جایگزینی انجام شد؛ عملیات mount، مالکیت و SELinux در این تست شبیه‌سازی شدند.

سورس C# و فایل‌های XAML به‌صورت ایستا بررسی می‌شوند. چون درخواست فعلی عدم ساخت EXE است، نصاب C# جدید کامپایل یا روی خودرو اجرا نشده است. تست‌های کنسولی پروژهٔ Tests برای مسیر جدید به‌روز شده‌اند؛ پس از بیلد می‌توان آن‌ها را اجرا کرد. موفقیت ابزار پچ روی لپ‌تاپ، جای تست نصب و بوت نسخهٔ جدید روی خودرو را نمی‌گیرد.

### نصب APK و مجوزها
از صفحهٔ اصلی «نصب APK» را انتخاب کنید. پس از انتخاب یک فایل APK، نصب روی همان دستگاه متصل و کاربر صفر انجام می‌شود. بعد از تأیید نصب، پنجرهٔ مجوزها باز می‌شود. فقط مجوزهای اعلام‌شده در مانیفست برنامه قابل انتخاب‌اند؛ انتخاب‌نکردن مجوز، دسترسی قبلی را لغو نمی‌کند. نصب برنامه‌های دیگر با AppOps مدیریت می‌شود و با مجوز عادی اشتباه گرفته نمی‌شود. اندروید ممکن است بعضی دسترسی‌ها را به‌دلیل نسخه، targetSdk یا سیاست خودرو نپذیرد؛ نتیجهٔ بررسی هر دسترسی در گزارش ثبت می‌شود. مجوز حافظه به معنی دورزدن scoped storage نیست.

این قابلیت به ابزار جدید، جاوا یا دانلود جداگانه نیاز ندارد. فایل APK پیش از نصب در نسخهٔ موقت ثابت کپی و نام پکیج و مجوزها از مانیفست باینری همان فایل خوانده می‌شوند. گزارش کامل از هر دو صفحه قابل کپی است. فایل‌های APK چندبخشی (APKS/XAPK) در این مرحله پشتیبانی نمی‌شوند.

بررسی این تغییر: نحو C# و ساختار XML رابط بررسی شد؛ بیلد و تست روی خودرو باید انجام شود.

## Publish خودکار و مسیرهای قابل انتقال
دو پوشهٔ `voyah-iran` و `voyah-iran-installer` را کنار هم نگه دارید. ابتدا APK امضاشدهٔ اندروید را در `voyah-iran/app/release/app-release.apk` بسازید؛ سپس پروفایل `WindowsSingleFile` را Publish کنید. پیش از جاسازی منابع در هر Build واقعی، `build/Prepare-Payload.ps1` خودکار اجرا می‌شود. اجرای جداگانهٔ اسکریپت دیگر لازم نیست. حالت `--no-build` برای Publish پشتیبانی نمی‌شود، زیرا منابع داخل EXE باید دوباره ساخته شوند.

ADB از `tools/platform-tools`، جاوا از `tools/runtime/java` و ابزار پچ از `tools/patch` خوانده می‌شوند. اسکریپت‌های نصب از پروژهٔ اندرویدی کنار نصاب گرفته می‌شوند. هیچ مسیر اختصاصی کاربر لازم نیست. نسخهٔ نمایشی باندل از `versionName` پروژهٔ اندرویدی خوانده می‌شود؛ بنابراین پس از هر تغییر نسخه حتماً APK را دوباره بسازید.

برای انتقال از طریق Git، فایل‌های موردنیاز پوشهٔ `tools` را نیز ثبت کنید (در صورت استفاده از Git LFS، محتوای واقعی فایل‌ها را دریافت کنید). APK خروجی و کلید امضای خصوصی لازم نیست در Git باشند؛ هر توسعه‌دهنده باید پیش از Publish، APK را بسازد. این فرایند خودکار، اندروید را بیلد نمی‌کند.

### رابط جدید مجوزهای نصاب
پنجرهٔ مجوزها به پنج گزینهٔ میکروفون، دوربین، موقعیت مکانی، نصب برنامه و اجرای پس‌زمینه محدود شده است؛ گزینهٔ «همه موارد» نیز در چیدمان سه‌ستونه قرار دارد. وضعیت ابتدا از دستگاه خوانده می‌شود و هر تغییر فوراً اعمال و بررسی می‌شود؛ دکمهٔ اعمال جداگانه حذف شده است. برخلاف نسخهٔ قبلی، برداشتن تیک دسترسی را لغو می‌کند. گزینه‌های نامرتبط یا دارای وضعیت نامشخص غیرفعال‌اند. تغییر گروهی در خطا تلاش می‌کند مقادیر قبلی را برگرداند و وضعیت واقعی را دوباره می‌خواند؛ خطاها در گزارش نصب هستند.

اجرای پس‌زمینه، AppOps پس‌زمینه و معافیت deviceidle همان برنامه را مدیریت می‌کند؛ جلوگیری از بستن فرایند توسط مدیریت اختصاصی وویا تضمین نشده و نیازمند تست خودرو است. نحو C# و XML بررسی شده؛ بیلد/Publish اجرا نشده است.
