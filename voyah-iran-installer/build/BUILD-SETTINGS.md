# تنظیمات بیلد محلی

فایل `Build Settings.cmd` در ریشهٔ پروژهٔ نصاب را در File Explorer اجرا کنید.
در Visual Studio نیز در Solution Explorer پوشهٔ **Build Settings** مسیر این فایل را نشان می‌دهد.

- رمز فایل امضا و در صورت نیاز رمز مستقل کلید را یک بار وارد و ذخیره کنید.
- تیک **اعمال پروتکشن** روشن: مسیر انتشار محافظت‌شدهٔ قبلی.
- تیک خاموش: Release امضاشده با کلید اصلی، بدون مرحلهٔ Protect و امضای مجدد آن؛ مناسب تست سریع.
- هر دو حالت، APK انتخاب‌شدهٔ همین بیلد را همراه واسط داخل نصاب قرار می‌دهند.
- در اولین Release اگر تنظیمات ندارید، همین پنجره خودکار باز می‌شود. بعد از ذخیره، بیلدهای بعدی سؤال نمی‌پرسند.
- برای عوض‌کردن رمز یا حالت، دوباره `Build Settings.cmd` را اجرا کنید.

رمزها با Windows DPAPI برای همین حساب ویندوز در `build/BuildSettings.local.json` ذخیره می‌شوند؛ فایل وارد Git یا payload نمی‌شود. پیش‌فرض پروتکشن روشن است. گزینهٔ «مینی‌فای و کوچک‌سازی منابع (R8)» مستقل از پروتکشن قابل خاموش‌کردن است. برای تست سریع هر دو تیک را بردارید. فعال‌کردن پروتکشن، R8 را هم فعال می‌کند. امضای Release در همهٔ حالت‌ها حفظ می‌شود. در حالت بدون پروتکشن، فشرده‌سازی بستهٔ نصاب سریع‌تر و احتمالاً حجم آن بیشتر است. تنظیمات قدیمی تا زمان تغییر، R8 را روشن نگه می‌دارند.

برای جلوگیری از تکرار Build و Publish ویژوال استودیو، بستهٔ موفق تا ۱۰ دقیقه و فقط در صورت ثابت‌بودن فهرست، اندازه و زمان تغییر ورودی‌ها و خود بسته دوباره استفاده می‌شود. تغییر کد، تنظیمات بیلد یا فایل‌های نصاب این استفادهٔ مجدد را باطل می‌کند. اجرای مستقیم Publish-Android.ps1 بدون -ReuseUnchanged این مرحله را رد نمی‌کند.
