# سرور اشتراک وویا ایران

پروژه C# / ASP.NET Core 8 با PostgreSQL 17، قابل بازکردن با `VoyahIran.Subscriptions.sln` در Visual Studio. API و پایگاه داده با Docker Compose اجرا می‌شوند. مسیرها نسبت به همین پوشه هستند.

## رفتار اشتراک

- اولین ثبت‌نام: ۳۰ روز اعتبار از زمان UTC سرور.
- اگر حداقل ۳ روز باقی باشد: تاریخ انقضا تغییر نمی‌کند.
- کمتر از ۳ روز: ۳۰ روز به انقضای فعلی اضافه می‌شود. اگر منقضی شده باشد، مبنا زمان فعلی سرور است.
- درخواست تکراری و هم‌زمان باعث تمدید چندباره نمی‌شود؛ تراکنش و قفل اختصاصی VIN استفاده می‌شود.
- اولین ثبت‌نام، انقضا و رویدادهای تمدید در PostgreSQL باقی می‌مانند. شمارنده فقط تمدید واقعی را می‌شمارد؛ ثبت اولیه و درخواست معمولی شمرده نمی‌شوند. `lastRenewedAt` قبل از اولین تمدید `null` است.
- VIN بلاک‌شده پاسخ ۴۰۳ می‌گیرد و تاریخ انقضایش تغییر نمی‌کند. بلاک قبل از اولین ثبت‌نام هم ممکن است. آنبلاک تاریخ و سابقه را حفظ می‌کند.
- همه تاریخ‌ها UTC هستند؛ شرط انقضا در اپ `now >= exp` است.

## امضا و کلیدها

پاسخ JWT با RS256 امضا می‌شود: `v, iss, aud, sub=VIN, iat, exp`. VIN کلید رمزگذاری نیست؛ دادهٔ عمومی است و برای جلوگیری از جعل مناسب نیست. محتوای توکن مخفی نیست اما بدون کلید خصوصی قابل تغییر معتبر نیست. اپ کلید عمومی محلی را بررسی می‌کند و از اینترنت کلید جایگزین نمی‌گیرد.

کلیدهای این محیط در `secrets/` ایجاد شده‌اند و از Git و Docker image کنار گذاشته شده‌اند. کلید عمومی متناظر در پروژه اندروید در `app/src/main/res/raw/subscription_public_key.pem` قرار دارد. فایل‌های secrets را امن و جدا از Git به سرور منتقل کنید. کلید خصوصی و رمز مدیریتی را داخل APK قرار ندهید. کلید فعلی را هنگام آپدیت یا ری‌استارت دوباره نسازید؛ نسخهٔ پشتیبان نگه دارید.

فقط برای ایجاد یک استقرار جدید با کلید جدید (اپ هم باید با public.pem همان کلید بیلد شود):

```powershell
dotnet run --project tools/VoyahIran.KeyTool -- secrets
```

ابزار از بازنویسی فایل‌های موجود جلوگیری می‌کند. `private.pem` کلید امضا، `public.pem` کلید عمومی، `admin-token.txt` رمز API مدیریتی و `db-password.txt` رمز PostgreSQL هستند.

## راه‌اندازی روی سرور لینوکس

پیش‌نیاز سرور: Docker Engine و Docker Compose. نیازی به نصب .NET یا PostgreSQL جداگانه نیست.

۱. سورس این پوشه و پوشه secrets موجود را به سرور منتقل کنید.
۲. فقط روی سرور لینوکسی، دسترسی فایل‌های secret را برای کاربر غیرروت کانتینر آماده کنید. UID تصویر .NET 8 برابر 1654 است:

```sh
chmod 700 secrets
sudo chown 1654:1654 secrets/private.pem secrets/admin-token.txt secrets/db-password.txt
sudo chmod 400 secrets/private.pem secrets/admin-token.txt secrets/db-password.txt
docker compose up -d --build
curl http://127.0.0.1:8080/health
```

۳. رکورد A دامنه `voyah-iran.ir` را به IP سرور اشاره دهید و پورت ۸۰ را باز کنید. نمونه server در `deployment/nginx.conf.example` را در Nginx فعال کنید. آدرس اپ `http://voyah-iran.ir/registerOrRenewSubscription` است؛ گواهی TLS یا ریدایرکت به HTTPS نیاز ندارد. تنظیم DNS و راه‌اندازی روی میزبان واقعی هنوز انجام نشده است.

شناسهٔ داخلی issuer توکن (`voyahiran.ir`) برای سازگاری ثابت مانده و آدرس شبکه نیست. اعتبار امضای RSA همچنان بررسی می‌شود؛ HTTP محرمانگی یا اصالت پاسخ‌های بدون امضا مانند خطای 403 را تضمین نمی‌کند.

API فقط روی localhost:8080 میزبان منتشر می‌شود و PostgreSQL پورت عمومی ندارد. دادهٔ PostgreSQL در volume پایدار است. `docker compose down -v` داده را حذف می‌کند؛ برای آپدیت معمولی فقط `docker compose up -d --build` کافی است. رمز دیتابیس را پس از ایجاد volume بدون تغییر متناظر رمز در PostgreSQL عوض نکنید.

## API خودرو

```http
POST /registerOrRenewSubscription
Content-Type: application/json

{"vin":"L123456789012345A"}
```

VIN مثال ساختگی است. VIN باید ۱۷ حرف/رقم بدون I/O/Q باشد. حروف کوچک به بزرگ تبدیل می‌شوند. پاسخ موفق:

```json
{"token":"<signed JWT>","expiresAt":"2026-10-15T12:00:00+00:00","serverTime":"2026-09-15T12:00:00+00:00","status":"registered"}
```

`status` یکی از registered/unchanged/renewed است. اپ تنها مقادیر داخل توکن امضاشده را معتبر می‌داند. پاسخ‌ها cache نمی‌شوند. VIN نامعتبر: ۴۰۰؛ بلاک: ۴۰۳؛ محدودیت نرخ: ۴۲۹؛ خطای گذرای دیتابیس: ۵۰۳. پاسخ ۴۰۳ نباید به کاربر «اینترنت را بررسی کنید» نمایش داده شود.

این API در سیاست فعلی رایگان است و صرف داشتن VIN ثبت‌نام را مجاز می‌کند؛ اثبات مالکیت خودرو یا پرداخت انجام نمی‌دهد.

## مدیریت

API مدیریت فقط از خود سرور یا تونل SSH روی `http://127.0.0.1:8080` در دسترس است؛ نمونه Nginx آن را عمومی نمی‌کند تا رمز مدیریت روی HTTP عمومی فرستاده نشود. ابزار را روی سرور اجرا کنید یا از تونل `ssh -L 8080:127.0.0.1:8080 USER@SERVER` استفاده کنید.

تمام مسیرهای `/admin/subscriptions` به هدر `Authorization: Bearer <admin-token>` نیاز دارند. رمز را از فایل بخوانید؛ آن را در URL، Git یا لاگ نگذارید.

```powershell
./tools/Manage-Subscription.ps1 -Action List
./tools/Manage-Subscription.ps1 -Action Get -Vin L123456789012345A
./tools/Manage-Subscription.ps1 -Action Block -Vin L123456789012345A -Reason 'مسدود توسط مدیر'
./tools/Manage-Subscription.ps1 -Action Unblock -Vin L123456789012345A
```

مسیرها:
- `GET /admin/subscriptions/?offset=0&limit=50`؛ حداکثر ۱۰۰ ردیف در هر صفحه.
- `GET /admin/subscriptions/{vin}`؛ شامل firstRegisteredAt، lastRenewedAt، renewalCount، expiresAt، blocked، blockedAt و blockReason.
- `POST /admin/subscriptions/block` با `{"vin":"...","blocked":true,"reason":"..."}`؛ برای آنبلاک false بفرستید.

`List` در ابزار PowerShell صفحه اول تا ۱۰۰ ردیف را نشان می‌دهد؛ برای صفحه‌های بعدی از پارامتر offset در API استفاده کنید. رویدادهای بلاک/آنبلاک نیز در جدول block_events ثبت می‌شوند.

## اتصال اندروید

اتصال در همین تغییر در پروژه اصلی پیاده شده و بررسی اشتراک در بیلد جدید فعال است. **قبل از توزیع APK باید این سرور با کلید متناظر روی دامنه راه افتاده باشد.** سپس APK را بیلد و اینستالر را دوباره Publish و نصب کنید؛ واسط هم برای خواندن VIN و کنترل اجرای پس‌زمینه تغییر کرده است.

- VIN از NVRAM شماره ۲۱، مطابق کد OEM خوانده می‌شود؛ مقدار دستی یا سریال اندروید جایگزین VIN نمی‌شود.
- توکن معتبر محلی، بدون انتظار شبکه، استفاده را مجاز می‌کند. هر ۶ ساعت و هنگام برگشت اتصال شبکه، تمدید در پس‌زمینه بررسی می‌شود؛ خطا با فاصله و تلاش مجدد مدیریت می‌شود.
- هنگام انقضا، پاسخ بلاک یا نبود توکن، پنجره بررسی اشتراک نمایش داده می‌شود. خطای VIN پیام جدا دارد.
- سرویس‌های ستاره، آسایش و رها نیز مستقلاً اعتبار را بررسی می‌کنند؛ تنظیمات ذخیره‌شده پاک نمی‌شوند. در انقضا ستاره به عملکرد اصلی برمی‌گردد، شنود و اتصال دکمه صوتی آزاد می‌شود و بازیابی درایو مود/انرژی اجرا نمی‌شود.
- واسط از ابتدا اجازه اجرای هوک دوربین ندارد؛ تنها با مجوز کوتاه‌مدت برنامه پس از تأیید اشتراک کار می‌کند. این مجوز از بوت قبلی باقی نمی‌ماند.
- تغییر ساعت یا سایر تنظیمات پایدار قبلی خودرو در زمان انقضا معکوس نمی‌شوند.
- بلاک در اولین درخواست بعدی به سرور اعمال می‌شود. خودرو کاملاً آفلاین تا انقضای توکن قبلی فعال می‌ماند. ساعت monotonic و کف زمان ذخیره‌شده جلوی عقب‌رفتن ساده ساعت را می‌گیرند؛ روی دستگاه روت‌شده، دستکاری هم‌زمان ساعت، فایل‌ها و خود APK قابل جلوگیری قطعی نیست.

## آزمون‌ها

تست‌های مستقل از دیتابیس:

```sh
dotnet run --project tests/VoyahIran.Subscriptions.Tests
```

تست کامل PostgreSQL با دیتابیس موقت مجزا (به دیتابیس اصلی وصل نمی‌شود):

```sh
docker compose -p voyah-subscription-test -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -p voyah-subscription-test -f compose.test.yaml down
```

یا TEST_DATABASE را به دیتابیس آزمایشی خالی اشاره دهید. تست‌های دیتابیس روی آن ردیف‌های آزمایشی می‌نویسند. پوشش: ثبت اولیه، مرز سه‌روز، انقضا، ماندگاری داده، درخواست‌های هم‌زمان، سابقه و شمارنده، بلاک/آنبلاک و بلاک قبل از ثبت‌نام.

در محیط توسعه فعلی: بیلد سرور و کامپایل اندروید موفق؛ ۱۹ بررسی سرور و ۹ تست امضا، زمان و کنترل اجرای سرویس‌های اندروید موفق. توکن ساخته‌شده با C# در تست اندروید تأیید شده است. اجرای یکپارچه PostgreSQL/Docker و تست روی خودرو هنوز انجام نشده‌اند؛ Docker روی این لپ‌تاپ موجود نیست.

لاگ سرور VIN را به اثر انگشت تبدیل می‌کند و توکن‌ها و رمزها را ثبت نمی‌کند. لاگ اندروید با برچسب Subscription قابل پیگیری است.

مراجع پیاده‌سازی: [PostgreSQL advisory locks](https://www.postgresql.org/docs/17/explicit-locking.html#ADVISORY-LOCKS)، [Docker Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/).


## ارتقای ستون‌های تاریخ
هشت ستون تاریخ به timestamptz تبدیل می‌شوند. تبدیل Unix seconds با to_timestamp در یک تراکنش هنگام شروع سرور انجام می‌شود و قابل اجرای مجدد است. قالب توکن و API حفظ شده است.
SQL تبدیل را به‌تنهایی روی سرور قدیمی اجرا نکنید. باینری قدیمی با ستون‌های جدید سازگار نیست؛ بازگشت به نسخهٔ قبلی نیازمند بازیابی بکاپ قبل از ارتقا است.
پس از انتقال سورس جدید، در پوشهٔ پروژهٔ سرور به ترتیب اجرا کنید (فقط پس از موفقیت مرحلهٔ قبل):

    docker compose stop subscriptions
    backup="subscriptions-before-dates-$(date +%Y%m%d-%H%M%S).dump"
    docker compose exec -T db pg_dump -U voyahiran -d voyahiran -Fc > "$backup"
    test -s "$backup"
    docker compose up -d --build subscriptions
    docker compose logs --tail=80 subscriptions

کانتینر db و volume را حذف نکنید. فایل بکاپ را نگه دارید. اتصال/جدول را در pgAdmin رفرش کنید.
نمایش ساعت تابع timezone نشست است؛ برای مشاهده به وقت ایران در Query Tool:

    SET TIME ZONE 'Asia/Tehran';
    SELECT * FROM subscriptions;

تست مهاجرت با compose.test.yaml، داده‌های قدیمی، NULL، تاریخچه، بلاک، اجرای مجدد و تمدید پس از تبدیل را بررسی می‌کند.
