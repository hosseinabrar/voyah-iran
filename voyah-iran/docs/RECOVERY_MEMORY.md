# حافظهٔ بازیابی انرژی

گزینهٔ «ذخیره سطح بازیابی انرژی» در تب «آسایش» مستقل از حافظهٔ Drive Mode است. فعال‌کردن آن سطح معتبر فعلی را بدون تغییر خودرو ثبت می‌کند. تغییرات بعدی از بازخورد سرویس CAN دریافت می‌شوند و پس از پایداری ۴۰۰ میلی‌ثانیه ذخیره می‌شوند. خاموش‌کردن گزینه فقط ذخیره و اعمال خودکار را متوقف می‌کند.

داده‌ها در SharedPreferences خصوصی `energy_recovery_memory.xml` با commit ذخیره می‌شوند و از دفتر `drive_memory.xml` جدا هستند. ماشین حالت مشترک با محدودهٔ مجاز ۲ تا ۴ استفاده می‌شود: ۲ ضعیف، ۳ متوسط و ۴ قوی. مقدار اولیهٔ قوی هنگام بوت نباید مقدار ذخیره‌شده را بازنویسی کند.

## قرارداد استخراج‌شده

قرارداد با گزارش `Voyah_Free_318_Live_Mode_Analysis_FA.pdf` و فایل‌های دیکامپایل‌شدهٔ VehicleSetting و CanBusService تطبیق داده شد.

| مورد | مقدار |
| --- | --- |
| سرویس Binder | `qg.canbus` |
| متد نوشتن | `ICanBusService.setVehicleState`، transaction `0x3a` / ۵۸ |
| کلید نوشتن | `HUM_ENERGY_PTREGEN_LEVL`؛ ordinal `0x191` / ۴۰۱، value `0x26b` / ۶۱۹ |
| کلید بازخورد | `HUM_ENERGY_PTREGEN_LEVL_FB`؛ ordinal `0x237`، value `0x312` |
| سطح مجاز | ۲، ۳، ۴ |

نویسندهٔ مستقل، آرگومان‌های ثابت `su 0 service call qg.canbus 58 i32 1 i32 401 i32 619 i32 <level>` را بدون ساختن متن شِل اجرا می‌کند. عدد ۱ علامت وجود Parcelable است. این درخواست به سرویس OEM داده می‌شود؛ فریم خام CAN تولید نمی‌شود. کلاینت شنود CAN همچنان فقط خواندن و callback را انجام می‌دهد. محدودیت مدل یا بیلد اضافه نشده است.

مهلت فرایند ۸ ثانیه است. خروج صفر به‌تنهایی موفقیت نیست: پاسخ Binder باید فاقد exception باشد و ماشین حالت باید سطح مطابق را در بازخورد خودرو ببیند. مسیر نوشتن جدید هنوز روی خودرو آزمایش نشده است.

## ترتیب بازیابی و چرخهٔ اجرا

- هنگام بوت، اتصال مجدد یا چرخهٔ خاموش/روشن، مقدار ذخیره‌شده حفظ می‌شود و اعمال تا آماده‌شدن CAN و خودرو و سرعت معتبر صفر منتظر می‌ماند.
- اگر هر دو گزینه فعال باشند، ابتدا مود بازیابی و تأیید می‌شود؛ سپس حداقل یک ثانیه فرصت تثبیت داده می‌شود و سطح بازیابی انرژی اعمال می‌شود. در خطای مود، بازیابی انرژی تا تلاش مجدد یا خاموش‌کردن حافظهٔ مود منتظر می‌ماند.
- اگر فقط حافظهٔ انرژی فعال باشد، مستقل عمل می‌کند. خاموش‌شدن خودرو حتی هنگام انتظار برای مود به ماشین حالت انرژی می‌رسد تا مقدار قبلی محفوظ بماند.
- برای هر چرخه حداکثر یک درخواست خودکار ارسال می‌شود؛ پس از ۱۰ ثانیه بدون تأیید، خطا و امکان تلاش مجدد نمایش داده می‌شود. مقدار ذخیره‌شده حفظ می‌شود.
- سرویس مشترک با فعال‌بودن هرکدام از دو گزینه foreground باقی می‌ماند و از گیرندهٔ بوت شروع می‌شود. محدودیت‌های راه‌اندازی خودکار در سند حافظهٔ رانندگی توضیح داده شده‌اند.

پس از بازیابی، آخرین بازخورد پایدار ثبت می‌شود؛ این بازخورد الزاماً منشأ دستی ندارد. اگر تغییر مود از رابط کارخانه سطح انرژی را تغییر دهد، سطح واقعی جدید نیز می‌تواند ذخیره شود. فاصلهٔ یک‌ثانیه‌ای ترتیب بوت باید با زمان‌بندی واقعی خودرو بررسی شود.

## آزمون خودرو پس از اجازهٔ ساخت APK

1. فعال‌کردن در هر سه سطح، تغییر سطح از رابط کارخانه و تطبیق مقدار ذخیره‌شده.
2. بوت و خواب/بیداری با سطح ذخیره‌شدهٔ ضعیف یا متوسط و مقدار اولیهٔ قوی؛ تأیید حفظ حافظه و بازگشت سطح.
3. آزمون چهار ترکیب روشن/خاموش دو حافظه؛ بررسی ترتیب مود سپس انرژی و ادامهٔ سرویس وقتی فقط انرژی فعال است.
4. قطع CAN، رد روت، پاسخ خطادار Binder و نرسیدن تأیید؛ نبود تکرار بی‌پایان و حفظ مقدار قبلی.
5. خاموش‌کردن گزینه بدون تغییر سطح فعلی؛ ثبت ترتیب واقعی ACC، READY، MODE و بازخورد انرژی.

در این مرحله APK ساخته یا نصب نشده و فرمانی روی خودرو اجرا نشده است.
